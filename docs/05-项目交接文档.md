# 人物关系图谱项目交接

更新时间：2026-08-19  
接手入口：先读本文件（尤其 §1.2 当前进度与遗留问题），再读 `02-产品需求文档.md`、`03-技术设计文档.md`、`04-实施计划.md`。

## 1. 一句话目标

把人物关系整理做成一个本地优先、可随时唤起的轻量伴随插件：用户阅读小说、做研究或玩游戏时，可以快速记录人物、理解画像、查看直接关系和计算关系路径，而不必离开当前任务。

当前 React Web 应用是核心能力底座，不是最终产品形态。小说阅读是首个闭环，科研、真实社交、亲属称谓、游戏角色和地理叙事是后续扩展方向。

## 1.0 产品方向变更与当前任务（2026-08-24）

**插件形态变更**：侧边栏嵌入完整工作台（网页端翻版分屏，挤占阅读空间）改为**弹窗形态 + 功能分频**——快捷键唤起后弹出浮层，初始界面为文件夹/图谱列表与新建入口；进入项目后弹窗内只做查询与轻编辑（①添加人物/关系 ②句子解析 ③地理图添加/解析/缩放预览 ④修改基本信息），详细编辑跳全屏工作台。

**句子解析升级为核心功能**：阅读场景借鉴划词翻译的唤起方式——选中文本 → 浮出气泡 → 候选确认面板（人物/关系/特征/地点/事件分组）→ 确认写入并收起。解析候选必须经确认才落库，沿用 `commitCurrentProject` 提交语义。

**移动端方向**：后续阶段做原生 App，重点场景为平板阅读（内置阅读器优先，底部抽屉/悬浮球 + 触控画布），与网页端共享同一领域核心。当前不启动。

**当前任务**：网页端弹窗化与划词解析（W1–W5，见 `docs/04-实施计划.md`），完成定义：弹窗全链路通过 E2E；普通图与地理图弹窗内可添加人物/关系并完成句子解析；详细编辑跳转全屏工作台后数据一致；收起后原页面焦点与阅读位置不丢失。

技术路线（最简实现）：不重写应用，`App.tsx` 增加 `?host=popup` 模式渲染紧凑界面，复用领域命令、`SentenceParsePanel`、`GraphCanvas`/`GeographyCanvas` 与既有 IndexedDB；Chrome 扩展侧边栏 iframe 指向弹窗入口。P5 真实 Chrome 人工验证在弹窗化后重新执行（验证对象从"侧边栏"改为"弹窗 + 划词气泡"）。

**旅程图冻结决策（2026-09-16）**：旅程图不再作为可见前端图谱类型，不继续做母图—子图重构。代码、`journey` 数据和导入导出兼容性保留；前端隐藏创建、打开、编辑及地理图站点呈现。根因不是缺少一种图形布局，而是其站点、人物与事件归属重复了章节进度、关系和地点事实，却没有验证独立高频需求。仅当目标用户确实需要围绕明确人物/群体理解移动路径，且大部分阶段可由章节与事件地点自动推导时，才以“叙事线”重新评估。

## 1.1 当前交接断点：G0-R 连续地图内核已重建

**G0-R 已完成（2026-08-17）**：`GeographyCanvas.tsx` 已由 D3/SVG 原型重写为 MapLibre GL 连续地图内核。旧的 SVG/焦点国家/语义档位切换/静态 GeoJSON 过滤实现已删除。已验证的改进：

- 单一相机权威状态由 MapLibre 实例持有，语义比例尺（全球/洲际/国家/地区或省州）仅由 zoom 派生文案，不触发任何 `setCenter`/选国/换投影。
- 滚轮使用 MapLibre 原生 cursor-anchored zoom；拖动使用原生 pan；只有“适应全部节点”调用 `fitBounds`。
- 人物/关系覆盖物为 WGS84 GeoJSON source/layer，与底图同一投影同一帧，不保存屏幕坐标；右键连线、点击选中、右侧详情面板复用既有接口。
- 底图采用 OpenFreeMap 矢量瓦片（免 Key，`© OpenFreeMap` 署名），断网/未加载回退到内置世界轮廓 `public/map-data/world-outline.geojson`。
- 地名按 `min_zoom`/`rank` 分层并开启碰撞避让与同名去重；不显示道路/建筑/POI。
- 图层开关（显示边界/显示地名）只控制样式可见性。
- MapLibre 通过动态 `import()` 分包（约 932 kB 独立 chunk），主 JS 约 727 kB。
- 已知的旧故障（跳中国/跳北京/福建漂移/标签轨迹/空白切口/主线程卡顿）在本实现中不再出现：相机连续、覆盖物同帧、瓦片生命周期由 MapLibre 管理。

后续边界：地理图 PNG/JPG/PDF 完整导出不在本阶段范围；旅行叙事（G3）、势力范围（G4）、AI 地名匹配（G5）与容量/版权验收（G6）留待下一阶段。底图端点与许可证记录见 `docs/06-地图数据与许可证.md`。

接手者仍须保护四条边界：相机只有地图实例一份权威状态；滚轮围绕鼠标缩放；人物只有在点击“适应全部节点”时才能改变相机；节点、关系线、标签和底图必须共享同一投影与同一渲染帧。

**四、经验教训（本可避免、却耗费了大量时间）**

1. **外部服务接入前未按目标网络环境验证可达性**。官方 Nominatim（openstreetmap.org）在开发环境可用、国内用户网络不可达，导致第八轮先扩词表治标，用户反馈后才在第九轮换镜像治本。教训：接外部服务（解析、瓦片、字体、LLM）之前，先按用户实际网络验证可达性、CORS 与限流，再写代码。
2. **"写入"路径缺少提交语义**。从第七轮插件化起，解析写入走 300ms 防抖 + `pagehide` 异步写库，页面卸载时不可靠，直到第十轮 E2E 稳定复现才修复。教训：用户可见的"保存/写入"必须落库后再返回，防抖只应服务于后台自动保存。
3. **E2E 失败归因草率**。parsing 持久化用例首次失败后单跑通过，被归为环境负载，问题延后一轮才确认。教训：E2E 失败至少复跑 2-3 次并盯住同一断言，判定"确定性 vs 偶发"，一次通过不能排除回归。
4. **竞态修复先改代码后补测试**。项目纪律是 TDD（先写复现失败的测试再改实现）；本次虽最终测试齐全，但复现用例应先行。

### 2026-08-18 第二轮（地理图体验续修 + G2 剩余任务，已完成）

针对上一轮 §1.2 列出的 4 个遗留问题与 G2 剩余任务，本轮一次性完成，全部通过测试与浏览器验证：

1. **投影改为 style 级 zoom 插值过渡（问题①的核心）**：`buildBasemapStyle` 顶层 `projection` 声明 `zoom 0.8 → vertical-perspective、1.4 → mercator` 插值表达式；删除 `syncLevel` 中 `setProjection` 硬切换与 `isStyleLoaded` 守卫。MapLibre 6.4.0 原生支持该机制（style-spec `projection` 为 zoom 插值表达式，`GlobeProjection.transitionState` 在 globe 与 mercator 间连续插值）。效果即 Apple 地图式平滑过渡：放大进入平面、缩小回到 3D 球体，跨档不触发 style 重载。
2. **联网地理解析接回（问题②）**：`geocoding.ts` 的 `geocodePlace` 升级为 `geocodeCandidates`（Nominatim，limit=5、限频 1 req/s、User-Agent、localStorage 缓存唯一结果）；`GeographyCanvas` 自动解析未匹配人物——本地已知地点与唯一网络结果直接落点（`status: "auto"`），多个同名结果展示候选由用户确认（`status: "confirmed"`），解析失败进托盘并支持重试；`Person` 新增可选 `geo` 字段（label/经纬度/countryCode/continent/status），随 JSON 导出导入，"地区/势力"文本变化时清除旧坐标重新解析。
3. **关系类型箭头语义（问题③）**：`geography-relationship-arrows` symbol 层沿 line 放置——directed 单箭头 `▶`、bidirectional 双向符号 `⇄`、undirected 实线无箭头、contact 虚线无箭头（原有 `line-dasharray`）；选中高亮与箭头叠加可读。
4. **底图信息补全（问题④）**：下载真实瓦片取证后扩展 `buildBasemapStyle`——`place` 新增 country/state/province/suburb 分层（rank/minzoom 密度预算）、`boundary` 新增 admin_level 6/8（z10/z12 起）、`water` 新增 river 面（z8 起）、新增 `waterway` 河流径流线（z3 起）与 `water_name` 河流名层；全部遵守碰撞避让与人物优先。
5. **G2 剩余**：地理图观察进度淡化（未来人物/关系降透明度）、搜索定位适配到所选人物、图层开关状态随刷新保留（localStorage）、加载失败仅由 WebGL/库初始化触发并支持重试（瓦片级错误回退到离线轮廓，不再整图报错）。

质量基线更新：单元测试 24 文件 / 139 用例全部通过；E2E 7/7 通过（新增"网络解析唯一+歧义确认"与"观察进度+搜索定位"两条地理图链路）；lint 0 errors、typecheck、build 通过（主 JS 738 kB + MapLibre 932 kB 动态分包）。

### 2026-08-18 第三轮（审阅修复：投影阈值/拖动锁定、箭头与双向线、编辑即保存、加载占位）

针对用户审阅反馈完成四项修复，均通过测试与浏览器验证：

1. **投影阈值与拖动稳定性**：球↔平面过渡区间从 0.8–1.4 提高到 **2.6–3.4**（3D 球保持到洲际档，便于在球体上查看跨区域节点）；新增"投影只响应缩放手势"机制——`dragstart` 锁定当前投影为固定字符串，`zoomstart`（非拖动）恢复插值表达式获得平滑过渡，`zoomend` 再锁定，彻底消除拖动导致 zoom 抖动引发的球↔平面突变。
2. **关系箭头改为矢量图标并贴合端点**：箭头从沿 line 重复摆放的文本 `▶` 改为运行时 `addImage` 生成的箭头图标（尖端在右缘），`icon-anchor: "right"` 使尖端精确落在目标节点坐标，图层顺序移到节点之上；`icon-ignore-placement` 保证渲染。**双向关系改为两条并行反向线**（`line-offset` ±4）+ 两端各一个指向对应端点的箭头，视觉呈 "⮂"。
3. **关系编辑"离开即保存"**：详情面板编辑（关系类型/端点/说明与人物名称）在点空白或点关闭按钮离开时自动提交，不再出现"视图已变但未保存、离开后恢复原样"的割裂。
4. **加载阶段不再空白**：loading 期间显示深色占位 + 旋转 spinner；`offline-outline` 默认可见（style 就绪但瓦片未到时显示世界轮廓，瓦片就绪后由运行时隐藏）；打开地理图时在 App 层预取 MapLibre 动态分包，缩短首屏等待。

质量基线：单元测试 24 文件 / 139 用例；E2E 8/8（新增"过渡阈值附近拖动锁定投影"回归）；lint 0 errors、typecheck、build 通过。

**遗留：关系线样式细节调整（等待用户视觉确认）**。当前箭头已改为矢量图标并贴合端点、双向线已改为两条并行反向线，但以下细节需要真实视觉反馈后才能定稿，AI 无视觉能力无法自行判断像素级效果：

- 箭头尖端与目标节点的接触程度（当前尖端落在节点中心，可能需改为顶到节点边缘并留出安全间隙）；
- 双向线 `line-offset` 偏移量（当前 ±4px，需确认视觉上是否足够分离、是否与箭头衔接自然）；
- 箭头图标大小（当前 `icon-size: 0.9`）与颜色（选中红色/默认蓝紫）在 1920×1080 视口下的可读性；
- 长距离关系线（跨洲）上箭头方向与线的贴合度（球面大圆 vs 屏幕直线的视觉差异）。

调整方式：用户提供截图或具体描述后，修改 `GeographyCanvas.tsx` 中 `arrowFeature` 的端点偏移、`createArrowIcon` 的图标形状、双向线的 `line-offset` 数值与箭头 `icon-size`。

### 已确认的问题与成因（当前未修复，属下一阶段任务）

**问题 ①：加载慢、卡顿、缩放区域空白、球↔平面切换异常**

现象：首次进入加载耗时很长；缩放跨档时部分地区整片空白；从平面放大回不去球体；洲际视图缩放时信息加载不出来。

成因：
- **加载慢**：MapLibre chunk（约 932 kB）动态懒加载 + OpenFreeMap 远程瓦片按视口拉取；首次打开需下载 chunk 和瓦片，dev 模式尤其明显。
- **球↔平面切换卡顿/空白**：`map.setProjection()` 的 globe↔mercator 是**硬切换**，会触发 style 重新解析与瓦片重新拉取，切换瞬间视口空白；`syncLevel` 里 `isStyleLoaded()` 守卫在 style 重载期间阻止了进一步切换，导致"回不去球体"。
- **缩放空白**：OpenFreeMap 瓦片按视口动态加载，未缓存区域在瓦片就绪前显示背景；globe 投影下高纬度/背面瓦片加载策略与 mercator 不同，跨档时尤其明显。

**问题 ②：节点 > 2 时，后续人物即使填写"地区/势力"也无法地理匹配**

成因：`GeographyCanvas` 解构出 `geocode` 后执行 `void _geocode`——**完全弃用了网络地理解析**。人物地点只走 `geocoding.ts` 的本地 16 个硬编码地点（`resolveKnownPlace`）；超出内置地点的一律进"位置待匹配"托盘。这是重写时丢失的能力：旧 D3 版本有 `geocodePlace`（Nominatim 网络解析 + 缓存），当前版本未接回。

**问题 ③：关系类型无法在视图中区分（只有线，无箭头/双向/虚线）**

成因：`geography-relationships` 是单个 `line` layer，paint 只用 `line-dasharray` 区分 `contact`（虚线）；`directed`/`bidirectional`/`undirected` 的箭头语义**未实现**。MapLibre 的 `line` layer 本身不画端点箭头，需要 `symbol` layer 或图标层配合。

**问题 ④：底图信息缺失（国家名、行政区划、核心城市、河流径流）**

成因：`buildBasemapStyle` 是"极简信息样式"，启用的图层太少：
- `place` 只显示 `city/town/village`，未启用国家名（`country` class）等。
- `boundary` 只显示 `admin_level 2/4`，未启用更细的 `admin_level 0/6/8`（二级/州省内部）。
- `water` 只显示 `ocean/lake`，**未启用 `waterway`**（河流径流）与 `water_name` 的河流名。
- 未启用行政区划核心城市的名称与位置（`place` 的 `rank` 过滤过严、`minzoom` 偏高）。

### 对策与技术路线（下一阶段实施）

- **① 加载与切换稳定性**：
  - 评估投影切换方案：避免 globe↔mercator 硬切换触发 style 重载（可考虑仅 mercator + 相机旋转模拟球体，或研究 MapLibre globe 投影与 mercator 的平滑过渡能力/降级策略）。
  - 底图瓦片优化：给 OpenFreeMap source 配置 `minzoom/maxzoom` 与缓存上限；增加"加载中/重试"状态；必要时评估本地缓存或断网轮廓增强。
  - 性能：MapLibre 已动态分包，进一步考虑 `maplibre-gl` 的 `worker` 与瓦片预取策略。
- **② 恢复网络地理解析**：重新启用 `geocode` prop → `geocodePlace`（Nominatim + localStorage 缓存），本地已知地点优先，未知地点联网解析、唯一结果自动放置、歧义结果列出候选；解析失败进入托盘并保留可重试入口。需注意 Nominatim 使用规范（限频、用户代理）。
- **③ 关系类型视觉语义**：用 `symbol` layer（图标箭头）或每类型独立 `line` layer + `line-dasharray`/端点 marker，使 `directed`（单向箭头）、`bidirectional`（双向箭头）、`undirected`（无箭头）、`contact`（虚线）在图中可区分；与 `GraphWorkspace` 的关系类型选择联动。
- **④ 底图信息补全**：在 `buildBasemapStyle` 扩展——`place` 增加 `country`/`province`/`suburb` 分层（按 `rank`/`minzoom` 密度预算）；`boundary` 增加 `admin_level 0/6/8` 分级；新增 `waterway` 河流层与 `water_name` 河流名；城市/州省核心地名按重要度显示。沿用 G0-R 的密度预算（rank/min_zoom/碰撞避让），不恢复道路/建筑/POI。

## 1.3 遗留问题的审查要点（供接手者精确诊断）

> 以下不是解决方案，而是**诊断时须逐项核实的检查点**。每个检查点都标注了从哪一层取证（代码 / 网络 / 浏览器 DevTools），以便把"猜测"变成"确认"。

### 针对问题①（加载慢 / 投影切换空白 / 回不去球体）

- **A1 瓦片加载耗时取证**：用 DevTools Network 过滤 `openfreemap` 请求，记录一次从加载到首屏就绪的瓦片请求数量、耗时分布、有无 429/超时/缓存未命中。区分"网络/远端慢"与"前端逻辑慢"。
- **A2 投影切换是否触发 style 重载**：在 `setProjection()` 前后分别监听 `style.load`/`styledata`/`sourcedata`/`idle` 事件并打点，确认 globe↔mercator 切换是否导致 style 重解析与瓦片重新拉取（这决定"切换空白"的根因）。
- **A3 syncLevel 守卫行为**：在 `syncLevel` 里临时记录 `getZoom()`、`levelNameForZoom()`、`isStyleLoaded()`、`getProjection().type`，还原"从平面放大回不去球体"时的调用序列——是 `isStyleLoaded()===false` 拦截了切换，还是 `setProjection` 抛错，还是事件根本未触发。
- **A4 相机事件频率与抖动**：滚轮/拖动连续操作时，`move`/`zoom` 事件触发 `syncLevel` 的频率；确认投影切换是否只发生在语义档位跨越（1.5 阈值）时，而非每次移动。
- **A5 空白区域的分布特征**：分别在 globe 档（高纬度、经度 180°附近、背面）与 mercator 档（跨国家、海边）缩放，记录空白出现的位置与是否随时间恢复；判断是瓦片未缓存、投影裁剪、还是父子瓦片切换缺口。
- **A6 首开时序分解**：用 Performance 面板分解首次打开耗时（主 JS chunk 下载 → MapLibre 初始化 → style 就绪 → 首屏瓦片），确认瓶颈环节；同时对比 dev 与 `vite preview`（生产）的差异。
- **A7 架构级取舍**：评估"是否必须 globe↔mercator 双投影"。若改用单一 mercator + 相机旋转/倾斜模拟"球体感"，能否同时满足 PRD 13.3（全球档 3D 地球）与 13.4（连续相机）——这是决定后续改动方向的关键审查点。

### 针对问题②（节点 > 2 无法地理匹配）

- **B1 确认 geocode 弃用链路**：`GraphWorkspace.tsx` 是否有向 `GeographyCanvas` 传 `geocode` prop；组件内 `_geocode` 被 `void` 的完整位置；确认"网络解析从未被调用"而非"调用了但失败"。
- **B2 匹配精度**：审查 `resolveKnownPlace` 的 substring 匹配（`normalized.includes(term)`）——"北京"是否可能误匹配"北京路"等；列出 16 个内置地点及其 terms，评估覆盖与误报。
- **B3 未匹配托盘过滤条件**：核实 `unmatchedPeople` 的判定（`person.affiliation && !resolveKnownPlace(...)`）是否会把"有地区值但解析失败"与"未填地区"混在一起；PRD 要求托盘是"已填但待确认"，应确认分类边界。
- **B4 Nominatim 接入可行性**：审查现有 `geocodePlace`（限频 1 req/s、User-Agent、CORS、失败重试、localStorage 缓存、歧义候选）是否可直接复用；`src/features/geography/geocoding.test.ts` 当前只测本地解析，需补网络解析的测试策略（mock fetch）。
- **B5 缓存与去重**：确认解析结果的缓存键（归一化地点文本）、重复人物共用同一地点的命中、以及"唯一结果自动放置 / 同名候选需确认"两条路径都已有数据模型支撑（`GeoLocation` 是否有 countryCode/continent 用于候选区分）。

### 针对问题③（关系类型无箭头语义）

- **C1 四类关系视觉映射表**：明确 `directed`（单向箭头，source→target）/ `bidirectional`（双向箭头）/ `undirected`（无箭头）/ `contact`（虚线）各自应有的呈现，与 `RelationshipKind` 逐一对应，确认当前实现缺了哪几类。
- **C2 MapLibre 箭头方案评估**：对 `geography-relationships` source，比较可行方案——`symbol` layer + `symbol-placement:"line"` + 箭头图标；按 kind 拆多个 `line` layer 各配端点 marker；或自定义 `line-pattern`。记录各方案在 3000 条关系下的性能与实现成本。
- **C3 更新链路**：关系类型修改后，`relationshipsGeoJson` 是否重新生成并经 `setData` 更新图层（确认 `GraphWorkspace` 的 `connectFromCanvas`/编辑 → `onChange` → 组件 `useMemo` → `setData` 链路完整）；箭头样式是随 zoom 缩放、是否被视口裁剪。
- **C4 与密度/选中冲突**：箭头图标是否会与人物节点、底图标签碰撞（沿用 G0-R 的碰撞避让与"人物优先"原则）；选中态高亮（当前红/加粗）与箭头样式叠加是否可读。

### 针对问题④（底图信息缺失）

- **D1 数据存在性取证**：用 `querySourceFeatures` 或下载实际瓦片，逐层确认数据里确实有——`place` 的 `country/province/suburb` class、`boundary` 的 `admin_level 0/6/8`、`water` 的 `river` class、`waterway` 层存在且带 `name`。**不要只看 schema 声明，要验证真实数据**。
- **D2 字段语义核对**：`place.rank` 的取值范围与"值越小越重要"是否成立；`name:zh` 是否存在（决定是否优先中文地名）；`boundary.admin_level` 各档对应的真实行政区级别。
- **D3 密度预算校准**：对每个拟新增图层，按 rank/minzoom 定出分档阈值，评估 1920×1080 视口下的标签数量是否"适中且均匀"（对照 PRD 13.3 屏幕信息预算），避免重蹈"信息更多=标签更多"的教训。
- **D4 图层堆叠顺序**：新增图层（waterway 应盖在 land 之上、place 名在边界之上）相对人物/关系覆盖层的 z-order；确保人物与关系线始终在底图标签之上（G0-R.4 的优先级约束）。
- **D5 语义比例尺联动**：`country/region` 档位（zoom 3.2/5.5）切换时，各信息层是否按档位渐进显现（低档只显示国家/国界，高档显示州省/城市/河流），验证与 `levelNameForZoom` 的一致性。

## 5. 犯过的错误、根因和防复发规则

### 右键连线曾反复带动节点

根因是只处理 Cytoscape 的高层事件，没有在原生 `pointerdown/mousedown/contextmenu` 捕获阶段阻断右键拖拽；后来又出现“开始节点视觉跟随鼠标、第二次右键后复位”的假移动。最终做法是捕获阶段阻止右键默认行为，单独用 SVG overlay 绘制临时关系线，并保存/恢复源节点坐标。防复发：右键连线、左键拖动、画布平移必须作为三条独立输入状态机测试；禁止用移动真实节点来模拟临时线端点。

### 关系类型选择与画布样式不同步

根因是事件监听闭包持有旧 `relationshipKind`，以及新建关系和已有关系编辑走了不同更新路径。最终通过 ref 向长生命周期事件监听提供最新类型，并统一关系 `kind/symmetric` 的写入和 Cytoscape 投影。防复发：所有被 Cytoscape 原生监听器读取的 React 状态都用同步 ref；新建、预览、保存、重载四条路径必须共用同一类型映射并各有测试。

### 右侧关系表单看似可编辑但保存无效

根因是输入控件、局部编辑状态和项目数据没有形成完整的受控链路，关系说明还被渲染为静态文本。最终改成受控 state，提交时同时校验并更新名称、类型、说明和端点。防复发：一个可编辑字段必须具备“初始化 → 输入 → 校验 → 保存 → 重选后仍存在”的组件测试；仅显示控件不算完成。

### 端点下拉框点击范围和画布点选冲突

根因是原生 select/覆盖层命中区域不稳定，且画布普通选择与端点选择共用了左键事件。最终改为可搜索候选面板、点击外部关闭，并用明确的 `endpointPicking` 模式接管一次画布选择；空白点击退出并恢复鼠标。防复发：临时交互模式必须有唯一状态、明确进入/成功退出/取消退出，并覆盖点击外部测试。

### 节点拖动结果无法保留

根因是 Cytoscape 元素因项目更新被重建后又执行布局，显示位置覆盖了拖动坐标。最终在 `dragfree` 提交布局，重建元素时优先恢复项目布局，其次恢复当前画布位置。防复发：位置变化需验证“拖动后、其他字段更新后、刷新后”三个时间点，不能只看拖动瞬间。

### 把直接关系说明与关系计算混为一谈

现有说明只会生成类似“甲与乙存在双向‘同事’关系”的可读句子；用户真正要求的关系计算是跨多条边得到“二叔”等间接称谓并展示推导链。防复发：领域命名严格区分 `relationshipDescription`、`relationshipPath` 和未来的 `relationshipInference`，三者验收标准不得互相替代。

### 没有及时区分计划状态与真实完成状态

实施计划第 5、6 阶段此前仍标为未完成，而代码已经落地；搜索也曾在口头推进中被遗漏。防复发：每完成一个纵向切片，同时更新测试、实施计划和交接快照；回答“做了吗”必须以代码搜索和测试结果为证据，不凭上下文印象。

### 用关系图渲染思路模拟连续地图

根因是把全球、洲际、国家、地区或省州做成会重算中心、焦点国家和缩放系数的模板，并用全量 SVG path 模拟地图相机；人物适配、拖动、缩放、图层过滤彼此耦合。随后为解决卡顿加入局部过滤，为解决空白加入更多 GeoJSON，为解决跳跃又修改拖动公式，最终形成连锁回归。防复发：地图交互交给成熟的连续地图相机和瓦片生命周期；语义比例尺只能由 zoom 派生，不能驱动相机；性能优化必须减少处理数据量，不能只限制刷新频率。

### 把“信息更多”误解为“标签更多”

根因是没有定义每个 zoom 的信息层级和屏幕预算，直接为每个行政区、河流或湖泊几何生成文字。同名水体被拆成多段后重复标注，人口密集区域堆叠，数据稀疏区域仍然空白。防复发：使用重要性 rank、`min_zoom`、同名稳定 ID、碰撞避让和网格配额；人物及关系可读性始终高于底图标签数量。

### MapLibre 长生命周期监听的闭包陈旧

在 `GeographyCanvas` 中，`map.on("contextmenu"…)`/`mousemove` 等监听只在首次覆盖层创建时注册一次，其闭包引用的 `project.people` 是**首次渲染的旧值**（当时人物为空），导致后续新增人物后右键连线预览取不到起点坐标。防复发：凡是被 MapLibre 原生监听读取的 React 数据，必须通过 `ref`（如 `connectionSourceLocationRef`）或直接从 feature 的 `properties` 读取，不能依赖渲染闭包。

### style 未就绪时 addLayer 失败

在 style 尚未完全加载（`isStyleLoaded()` 为 false）时调用 `map.addSource/addLayer` 会抛 “Style is not done loading”，且 `getStyle()` 为 null、`load` 事件永不触发；style 里图层引用了未在 `sources` 中定义的 source 也会导致整个 style 被拒绝。防复发：底图必需的 source/layer（含经纬网、连线预览层）一律在 `buildBasemapStyle` 里预先定义，运行时用 `setData`/`setLayoutProperty` 更新，避免运行期 addLayer。

## 6. 接手后的工作纪律

功能或修复按测试驱动执行：先写会因缺少目标行为而失败的测试，再写最小实现；每次代码修改后至少运行相关测试、`npm run lint` 和 `npm run typecheck`，交付前运行全量 `npm test` 与 `npm run build`。不要因 UI 看起来正确跳过保存后的重选/刷新验证。

保持本地优先和事实边界：用户输入的人物、关系和事件是事实；搜索结果、路径、称谓和 AI 抽取是派生结果。派生结果默认不写回事实，除非用户明确确认。
