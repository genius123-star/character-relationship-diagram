# 人物关系图谱：需求澄清记录

## 当前产品判断

产品的共同底座是“人物关系图谱”：用户建立人物节点，为人物补充资料，以有方向、带类型的关系连接人物，并通过搜索和路径计算理解复杂人物网络。

首版只验证小说阅读场景，不同时承担科研知识管理、真实社交管理和完整亲属称谓计算。后续场景只有在首版证明人物录入、关系维护和图谱理解确实有用后再扩展。

## 首版目标用户与场景

目标用户是阅读人物众多、姓名陌生或跨越多代的小说时，难以记住人物身份和关系的个人读者。

核心任务：读者遇到陌生人物时，能快速查到“他是谁、还叫什么、何时出现、与已知人物有什么关系”，并在阅读过程中持续补充资料。

## 已确认边界

- 载体：桌面浏览器中的本地 Web 应用。
- 使用方式：单人使用。
- 数据：优先保存在本地，不要求账号和云同步。
- 首版场景：小说人物关系梳理。
- 后续候选：科研人物研究、真实社交画像、亲属称谓计算、浏览器插件。

## 首版核心闭环

创建作品 → 添加人物 → 记录人物资料 → 建立人物关系 → 搜索并定位人物 → 查看两人之间的关系路径。

## 待确认

需求澄清阶段已完成，暂无阻断 PRD 编写的待确认项。

## 已确认的关系规则

- 人物节点和人物关系均允许用户直接创建、编辑和删除。
- 关系类型采用“预设常用类型 + 用户自定义类型”。
- 用户录入的直接关系是事实源；系统不擅自修改事实源。
- 系统可根据已有连线计算两个人物之间的一条或多条关系路径。
- 计算结果用于显示，不自动保存为新的直接关系，避免产生重复或错误事实。
- 首版展示关系链及每一段关系，不把多段关系自动概括成新的自然语言称谓。

## 已确认的观察进度规则

观察进度 = 用户在当前工作区时间轴上选择的观察位置。它用于突出当前阶段已经出现的人物和已经生效的关系，不等同于防剧透。

- 底层采用通用时间轴，不把“章节”写死在人物或关系模型中。
- 不同工作区可使用不同时间轴单位：小说使用章节，科研使用日期、年份或历史节点，真实社交使用日期。
- 初版仅开放小说工作区，默认时间轴单位为“章”。
- 人物可记录首次出现位置；关系可记录开始生效位置。
- 开启观察进度后，当前位置及以前的节点和关系正常显示，之后的节点和关系淡化显示。
- 未填写时间轴位置的人物和关系始终正常显示。
- 初版不隐藏未来内容。AI 文件导入成熟后，可在同一机制上增加“隐藏未来内容”，形成真正的防剧透模式。

## 已确认的人物画像规则

- 创建人物时仅“名称”为必填项，其余资料均为选填项。
- 选填资料用于丰富节点信息，不阻断快速创建人物的主流程。
- 用户点击人物节点后，在详情区域查看和编辑完整画像。
- 基础字段包括：名称、别名、头像、简介、性格标签、身份标签、首次出现章节、备注。
- 人物事迹与人生轨迹统一为结构化事件，避免重复维护。
- 每条事件可记录：章节、事件标题、事件描述、地点；除事件标题外均可选填。
- 多条事件按章节顺序组成该人物的轨迹。

## 已确认的人物关系字段

- 关系采用有方向记录，同时支持从两个端点阅读。
- 必填项为起点人物、终点人物和正向关系名称。
- 可选项为反向关系名称、关系描述、开始章节和结束章节。
- 对称关系（如朋友、夫妻、敌对）只需填写一个关系名称，两个方向显示相同名称。
- 非对称关系（如母亲、儿子、老师、学生）可分别填写正向和反向称谓。
- 系统沿查询方向选择正向或反向称谓，组合并展示关系路径。

## 已确认的搜索与定位规则

- 人物名称不要求唯一；系统使用不可见的内部 ID 区分重名人物。
- 搜索匹配人物名称、别名、简介、性格标签和身份标签。
- 用户可以连续选择多个搜索结果。
- 图谱定位并高亮选中的人物，以及这些人物之间的最短关系路径。
- 其他节点和关系淡化显示而不消失，保留人物所处网络的上下文。
- 用户点击图谱空白区域后恢复完整图谱的正常显示。

## 已确认的归类与颜色规则

- 首版仅实现用户可控、结果可解释的规则归类。
- 用户选择一个标签维度（如家族、阵营、身份），系统按照该维度下的标签值自动分配节点颜色。
- 同一人物可拥有多个标签；节点颜色只由当前选中的归类维度决定。
- 图例展示颜色与标签值的对应关系。
- 首版不实现基于简介、性格、事迹或观点文本的 AI 语义聚类。
- 首版不实现基于关系网络的自动社群划分或亲疏聚类。

## 已确认的图谱布局规则

- 图谱默认使用自动布局，并支持缩放、平移和一键适应全图。
- 节点之间具有碰撞约束，不允许覆盖或重合。
- 用户拖动节点时，周围未固定节点实时移动并保持最小安全距离。
- 用户拖动后的节点位置自动保存，并可将节点单独固定。
- 已固定节点不被自动布局或其他节点的拖动改变位置。
- 拖动节点接近固定节点时，拖动节点停留在最小安全距离外。
- “重新布局”仅重排未固定节点；“重置布局”解除全部固定并重新计算位置。

## 已确认的本地存储与交换规则

- 一部作品对应一个独立项目。
- 项目数据在浏览器本地自动保存，不依赖账号或网络连接。
- 用户可将完整项目导出为一个 JSON 文件，并通过该文件恢复或迁移项目。
- 导出内容包含人物、头像、事件、关系、标签、时间轴配置和布局位置。
- 首版不支持 Excel 或 CSV 导入导出。
- 后续 AI 文件解析产生的数据也转换为同一项目结构，再交给用户校对和导入。

## 已确认的编辑安全规则

- 首版支持最近 50 次撤销和重做。
- 撤销和重做覆盖人物、关系、事件、标签的新增、编辑、删除，以及节点位置变更。
- 一次连续拖动视为一次操作。
- 所有变更完成后立即自动保存。
- 删除人物前显示二次确认，并明确将删除的直接关系和人物事件数量。
- 删除人物只同时删除该人物的事件，以及以该人物为起点或终点的直接关系。
- 删除人物不会删除其他人物、其他人物的事件或不与该人物直接相连的关系。
- 关系路径为实时计算结果，不作为独立数据保存，因此无需级联删除。

## 已确认的容量与性能基线

- 单个项目至少支持 300 个人物、1,000 条关系，以及每个人物 50 条事件。
- 在上述规模下，搜索结果应在用户输入后 300 毫秒内出现。
- 节点拖动、画布缩放和平移应保持连续可操作，不出现明显停顿。
- 打开已有项目并显示可操作图谱的时间不超过 3 秒。
- 该基线用于覆盖复杂长篇小说；首版不为大型科研知识图谱预先扩展架构。

## 已确认的主界面状态

- 主界面由固定左侧控制栏、中间关系图谱和按需出现的右侧详情面板组成。
- 默认状态为“左侧控制栏 + 扩展关系图谱”，右侧详情面板隐藏，图谱占据其空间。
- 用户点击人物节点后选中该人物，右侧详情面板自动出现并展示人物画像，中间图谱相应收缩为三栏布局。
- 用户点击关系连线后选中该关系，右侧详情面板自动出现并展示关系名称、反向称谓、描述和生效章节等资料。
- 右侧面板根据当前选中对象在“人物详情”和“关系详情”之间切换。
- 用户点击图谱空白区域后取消当前选择，右侧详情面板自动隐藏，中间图谱重新扩展。
- 面板显示和隐藏时保持图谱当前缩放比例与视野中心，并确保所选人物仍在可见区域。
- 左侧控制栏在两种状态下始终显示，用于搜索、观察进度和颜色归类。

## 已确认的首版验收闭环

首版必须完整通过以下连续任务：

创建《百年孤独》项目 → 添加至少 20 个人物及画像 → 建立至少 30 条双向可读关系 → 拖动并固定节点且不发生重叠 → 按章节观察进度淡化未来内容 → 按家族标签着色 → 搜索并选择多个人物 → 高亮其最短关系路径 → 编辑人物和关系 → 撤销误操作 → 导出 JSON 后重新导入，数据与布局保持一致。

只有整条任务链全部通过，首版核心能力才视为成立。

## 当前明确不做

- 注册、登录、多用户协作和权限系统。
- 云端同步和跨设备同步。
- 浏览器扩展或论文写作插件。
- 自动从整本小说抽取人物和关系。
- 覆盖所有地域、辈分和婚姻规则的亲属称谓引擎。
