# 人物关系图谱技术设计

版本：v1.1（交接基线，2026-08-12）  
对应 PRD：v1.1  
状态：实现中

## 1. 技术判断

首版采用纯前端单页应用：浏览器负责界面、图谱计算、本地持久化和文件交换，不设置服务端。300 个人物和 1,000 条关系属于浏览器可直接处理的规模，图数据库、微服务、账号系统和云基础设施只会增加成本，不解决当前问题。

核心链路：用户操作 → 领域命令 → 内存状态更新 → 图谱派生计算 → IndexedDB 自动保存 → JSON 导入导出。

当前 Web SPA 是核心引擎和交互验证环境。最终插件化采用“共享核心 + 薄宿主”：领域模型、搜索、路径、推理和导入导出保持无宿主依赖；弹窗浮层、划词气泡、桌面壳或移动端 App 只负责唤起、尺寸适配、当前上下文关联与权限管理。现阶段禁止把浏览器扩展 API 或平台 API 写入 `src/domain`。

### 1.1 当前实现快照

截至 2026-08-12，项目已实现本地项目 CRUD 与自动保存、人物和关系 CRUD、右键可视化连线、四种关系类型、关系端点编辑、人物可选资料块及排序、事件排序、头像、颜色归类、节点拖动持久化/固定/碰撞避让、预览模式、搜索连续多选和无权最短路径高亮。关系说明可根据起点、终点、名称和类型生成并允许覆盖保存。

第七阶段已完成观察进度与间接关系推理；第八阶段已完成可靠 JSON 导入导出、头像交换、严格校验和原子导入；第九阶段已完成 500/3,000 性能基准、三条真实浏览器 E2E、基础无障碍检查与 README。规则库不是完整民俗称谓百科，未覆盖或含糊输入必须返回未知。Web v1.0 验收闭环已经完成，尚未实施浏览器插件宿主。

## 2. 技术栈

- React + TypeScript：界面与交互状态。
- Vite：开发服务器和生产构建。
- Cytoscape.js：节点、连线、缩放、平移、选择、布局与路径可视化。
- 原生 IndexedDB：项目文档与头像 Blob 的本地持久化。
- CSS Modules 或普通分层 CSS：样式；首版不引入组件库和 CSS-in-JS。
- Vitest + React Testing Library：领域逻辑与关键界面测试。
- Playwright：端到端验收闭环。

除 Cytoscape.js 外，不为图算法、状态管理、表单或数据库额外引入框架。短路径、导入校验、撤销栈和存储访问保持为小型项目内模块。

## 4. 数据模型

### 4.1 标识与通用类型

所有实体使用 `crypto.randomUUID()` 生成不可见 ID。名称不作为主键，允许重名和改名。

```ts
type EntityId = string;

interface ChapterPosition {
  kind: "chapter";
  value: number; // 正整数
}
```

首版只实现 `chapter`，但所有时间字段引用 `ChapterPosition`，避免把 `firstChapter` 等小说专用字段散落到算法和存储层。未来扩展日期或事件节点时替换为联合类型。

### 4.2 项目

```ts
interface ProjectDocument {
  schemaVersion: 1;
  id: EntityId;
  name: string;
  createdAt: string; // ISO 8601
  updatedAt: string;
  timeline: {
    kind: "chapter";
    label: "章";
    max?: number;
  };
  people: Person[];
  relationships: Relationship[];
  categories: CategoryDimension[];
  layout: Record<EntityId, NodeLayout>;
}
```

项目文档不内嵌头像二进制，只保存 `avatarAssetId`；头像 Blob 单独存储，避免每次编辑都复制和序列化图片。

### 4.3 人物与事件

```ts
interface Person {
  id: EntityId;
  name: string;
  aliases: string[];
  avatarAssetId?: EntityId;
  summary?: string;
  personalityTags: string[];
  identityTags: string[];
  firstAppearance?: ChapterPosition;
  notes?: string;
  categoryValues: Record<EntityId, EntityId[]>;
  events: PersonEvent[];
  createdAt: string;
  updatedAt: string;
}

interface PersonEvent {
  id: EntityId;
  title: string;
  position?: ChapterPosition;
  description?: string;
  location?: string;
}
```

校验规则：`Person.name.trim()` 和 `PersonEvent.title.trim()` 不得为空；其余字段允许缺省。

### 4.4 关系

```ts
interface Relationship {
  id: EntityId;
  sourcePersonId: EntityId;
  targetPersonId: EntityId;
  forwardLabel: string;
  reverseLabel?: string;
  symmetric: boolean;
  description?: string;
  startsAt?: ChapterPosition;
  endsAt?: ChapterPosition;
  createdAt: string;
  updatedAt: string;
}
```

校验规则：起点和终点必须存在且不同，`forwardLabel.trim()` 不得为空；`symmetric=true` 时反向读取使用 `forwardLabel`，否则优先使用 `reverseLabel`，缺失时显示“反向关系未定义”。同一人物对允许存在多条不同关系。

### 4.5 归类与布局

```ts
interface CategoryDimension {
  id: EntityId;
  name: string;
  values: CategoryValue[];
}

interface CategoryValue {
  id: EntityId;
  name: string;
  color: string; // #RRGGBB
}

interface NodeLayout {
  x: number;
  y: number;
  fixed: boolean;
}
```

颜色随标签值保存，保证导入后颜色一致。未分类人物使用固定中性色。

## 5. 运行时状态

持久化项目数据与临时视图状态严格分开：

```ts
interface WorkspaceViewState {
  selected?:
    | { kind: "person"; id: EntityId }
    | { kind: "relationship"; id: EntityId };
  searchQuery: string;
  selectedPersonIds: EntityId[];
  observationEnabled: boolean;
  observationPosition?: ChapterPosition;
  activeCategoryDimensionId?: EntityId;
  viewport: { zoom: number; panX: number; panY: number };
}
```

搜索文本、当前选择和观察进度属于视图状态，不进入撤销历史。节点位置、标签和业务资料属于项目数据，需要持久化和撤销。

## 6. 状态更新、撤销与自动保存

项目使用 React `useReducer` 维护，不引入全局状态框架。所有修改表示为可执行且可逆的领域命令：

```ts
interface HistoryEntry {
  label: string;
  redo: ProjectCommand;
  undo: ProjectCommand;
}
```

- 新增操作的逆操作是按 ID 删除。
- 删除操作在执行前保存被删实体及其直接依赖，逆操作完整恢复。
- 编辑操作保存字段修改前后的值。
- 连续拖动只在 `dragfree` 时提交一次位置命令。
- 撤销栈最多保留 50 条；执行新命令后清空重做栈。
- 头像 Blob 不放入历史栈；人物头像变更只记录旧、新 `assetId`。

每次领域命令结束后更新 `updatedAt`，并以 300 毫秒防抖写入 IndexedDB。`pagehide` 时对尚未写入的变更执行最后一次保存。界面显示“已保存/保存中/保存失败”，保存失败不得静默忽略。

## 7. IndexedDB 设计

数据库名：`character-graph`，版本：`1`。

对象仓库：

- `projects`：键为项目 ID，值为完整 `ProjectDocument`。
- `assets`：键为资源 ID，值包含 `projectId`、MIME 类型、文件名和 Blob。

索引：

- `projects.updatedAt`：项目首页排序。
- `assets.projectId`：删除项目时清理所属头像。

数据库访问集中在 `projectRepository.ts` 和 `assetRepository.ts`。不建立通用 Repository 接口；首版只有一种本地实现。

## 8. 图谱渲染与布局

### 8.1 Cytoscape 映射

- `Person` 映射为 Cytoscape node，节点 ID 等于人物 ID。
- `Relationship` 映射为 Cytoscape edge，边 ID 等于关系 ID。
- Cytoscape 元素是渲染投影，业务修改必须回到领域命令。
- 人物头像通过 Blob URL 显示；切换项目或卸载时调用 `URL.revokeObjectURL()`。

### 8.2 布局规则

- 初次进入或用户选择“重新布局”时运行 Cytoscape `cose` 布局。
- 固定节点在布局前锁定；只移动未固定节点。
- 节点尺寸包含头像、名称标签和安全间距；碰撞半径按实际渲染包围盒计算。
- 拖动过程中检测与相邻节点的包围盒交叠，对未固定节点施加最小位移。
- 与固定节点冲突时不移动固定节点，而将被拖动节点限制在安全距离外。
- 每一动画帧最多执行一次碰撞修正，避免拖动事件过密造成卡顿。

若 `cose` 在 300 节点基准下不能满足连续操作，再评估 Web Worker 或替换布局算法；首版不预先引入布局插件。

## 9. 搜索、观察进度与着色

### 9.1 搜索

项目载入后为每个人物生成小写搜索文本：名称、别名、简介、性格标签和身份标签拼接。输入经 150 毫秒防抖后对最多 300 条记录线性匹配；该规模无需全文索引库。

### 9.2 路径

关系按无向邻接表参与连通路径搜索，但遍历每条边时保留实际方向。使用广度优先搜索计算无权最短路径；邻接边按关系创建时间和 ID 稳定排序，确保多条等长路径时结果可复现。

两个以上人物被选择时，以第一位选中人物为锚点，分别计算其到其他选中人物的最短路径，并高亮所有结果的并集。任一目标不可达时单独标记该人物为“未找到路径”。

### 9.3 观察进度

- 人物满足 `firstAppearance.value > 当前章节` 时淡化。
- 关系满足 `startsAt.value > 当前章节` 时淡化。
- 未填写位置时正常显示。
- 搜索路径高亮优先级高于普通样式，但未来内容仍保留浅色/虚线提示，不伪装为当前已发生。

### 9.4 着色优先级

选中/路径高亮 → 观察进度淡化 → 当前归类颜色 → 默认颜色。样式只由数据和视图状态计算，不写回业务数据。

## 10. 自适应面板

工作区使用 CSS Grid：固定左栏、弹性画布、可选右栏。

- 无选择：`260px minmax(0, 1fr)`。
- 有选择：`260px minmax(0, 1fr) 360px`。
- 面板切换采用约 180 毫秒宽度过渡。
- 切换前记录视口中心对应的图谱坐标，切换后恢复该坐标与 zoom。
- 若选中对象落到新可视区域外，只执行最小平移将其带回视野，不调用全图适配。
- Cytoscape 容器尺寸变化后调用 `resize()`，再恢复视口。

人物和关系表单共用详情面板容器，但使用两个明确组件，不构造动态表单框架。

左侧控制栏固定为五个同层级区块：项目统计 → 观察进度 → 搜索定位 → 多节点关系计算 → 颜色归类。各区块使用统一的标题字号、12px 内容字号、12px 内部间距和 22px 上下留白。搜索定位只保存一个 `searchFocusId`；关系计算独立保存 `calculationSourceId` 与 `calculationTargetId`，避免搜索行为隐式改变推理输入。

## 11. JSON 交换格式

导出文件结构：

```ts
interface ExportBundle {
  format: "character-graph";
  schemaVersion: 1;
  exportedAt: string;
  project: ProjectDocument;
  assets: Array<{
    id: EntityId;
    mimeType: "image/jpeg" | "image/png" | "image/webp";
    fileName: string;
    dataUrl: string;
  }>;
}
```

导入按以下顺序执行：读取文件 → 限制大小 → JSON 解析 → 顶层格式校验 → 实体字段校验 → 引用完整性校验 → 头像解码校验 → 在内存中生成完整导入结果 → 单次事务写入。任何一步失败都不得修改现有数据。

首版 `schemaVersion` 只接受 `1`。未来版本通过独立迁移函数逐级转换，不在首版预留插件系统。

图谱图像导出由 `GraphCanvas` 暴露宿主无关的 `GraphImageExporter`：Cytoscape 按元素完整包围盒生成全图 PNG/JPG，不修改当前视口；最长边限制为 4,096 px。PNG 使用无损输出，JPG 使用不透明浅色背景和 0.94 质量。PDF 将同一份 JPG 快照嵌入单页 A4，根据图谱长宽比选择横向或纵向并等比缩放，保证节点不被裁切。JSON 与图像导出共用一个格式选择弹窗，但保持不同职责。

## 12. 数据安全与输入边界

- 所有用户文本均作为纯文本渲染，不使用 `dangerouslySetInnerHTML`。
- 头像仅接受 JPEG、PNG、WebP，并限制单张 5 MB；解码失败拒绝保存。
- 导入 JSON 默认限制 50 MB，超限直接拒绝。
- 导入时忽略原型链危险键，不将未知对象合并到运行时对象。
- 导入成功前不删除或覆盖当前项目。
- 删除项目采用 IndexedDB 单事务删除项目文档和所属资源。
- 应用不上传项目、头像或使用行为数据。

## 15. 架构风险与升级条件

- 原生 IndexedDB 代码若出现多次真实事务错误或迁移需求，再引入轻量封装；首版不预装。
- Cytoscape `cose` 若在基准数据上不能满足拖动和布局性能，先用性能分析确认瓶颈，再选择 Web Worker 或专用布局插件。
- 单文件 JSON 若因大量头像频繁超过 50 MB，再改为 ZIP 包；首版保持单文件的可理解性。
- 只有账号、同步或协作进入已批准范围时才增加服务端；不能为假设中的未来需求提前建设。

## 16. 架构决策记录

### ADR-001：纯前端本地应用

选择：无后端 SPA。  
理由：满足单人、本地、离线和隐私要求，部署与维护成本最低。  
代价：没有跨设备同步，浏览器数据需依赖导出备份。

### ADR-002：文档存储而非图数据库

选择：项目文档存入 IndexedDB，图结构在内存中派生。  
理由：数据规模小，查询集中在单个项目，浏览器中无须运行图数据库。  
代价：未来超大科研图谱需要重新评估索引和计算方式。

### ADR-003：Cytoscape.js 作为唯一图谱依赖

选择：用 Cytoscape.js 承担渲染、交互和基础布局。  
理由：避免自行实现完整图形引擎，同时保留对样式和事件的控制。  
代价：复杂拖动避让需要少量项目内逻辑，并须通过 300 节点基准验证。

### ADR-004：Web 核心与插件宿主分离

选择：先把 Web SPA 做成可复用核心，再增加浏览器侧边栏/浮层宿主。  
理由：搜索、图谱、存储和推理能力可独立验证；插件权限、跨站注入和桌面 Overlay 不应污染领域层。  
代价：现有 IndexedDB 和 UI 尺寸需要在插件阶段抽象宿主适配层；不同平台不能保证一次开发全部复用。

### ADR-005：文件夹共享事实与图谱视图分离

选择：人物、关系、资料和事件归文件夹共享库所有；图谱只保存成员引用、关系引用、布局、进度和类型专属配置。  
理由：跨人物关系图、地理图和旅程图编辑时只有一份事实来源，不产生复制冲突。  
代价：必须为现有项目执行无损迁移，并在永久删除时以事务清理文件夹内全部视图引用。

### ADR-006：系统真实地图而非用户底图

选择：地图采用全球、洲际、国家、地区或省州四档连续语义比例尺，而非两个手动切换的独立视图。`determineViewLevel` 根据已解析地点的 `countryCode` 与 `continent` 判定自动档位；全球档使用正射投影，其余档位使用墨卡托投影。滚轮越过各档阈值时可依次进入更细一级，即使自动范围仍是洲际；用户平移或缩放后设置手动锁，`适应全部节点` 清除手动锁并按所有节点重新取景。仅渲染行政区划、海岸线、主要湖泊、河流、山地图例和可选经纬网。  
理由：满足小说、社会事件和学派人物的空间解释需求，同时控制视觉噪声、数据体量与维护成本。  
代价：首次地名解析和地图分块允许联网；地名解析结果必须同时保存国家代码与洲信息才能正确取景；不支持卫星影像、虚构地图、历史疆域、等高线或真实高程。

地理节点沿用普通关系图的圆形视觉语义，只在 DOM 中保留可访问名称；地点和完整资料由选中节点后的右侧资料面板展示，避免节点卡片遮挡关系线。关系和人物事实仍来自文件夹共享库，投影坐标只属于当前地理视图。

### ADR-007：以 MapLibre + 矢量瓦片替换 SVG 全量 GeoJSON 地图

状态：**已决定，下一阶段执行；ADR-006 中“语义比例尺”的产品目标保留，现有 D3/SVG 技术实现废弃。**

选择：使用 MapLibre GL JS 维护唯一地图相机并通过 WebGL 渲染；底图采用 MVT 矢量瓦片，优先评估远程 PMTiles 单文件归档。PMTiles 通过 HTTP Range Request 只读取当前视口所需瓦片，适合联网为主、插件体积受限的产品。地图样式只启用 `earth/coastline`、`boundaries`、`water`、`places` 和精选 `natural/landcover`；道路、建筑、POI、卫星和等高线不进入默认样式。

相机所有权：地图实例的 `center/zoom/bearing/pitch/projection` 是唯一权威状态。语义层级由 zoom 派生，只用于界面文案和样式表达式，不触发 `setCenter`、重新选国或数据源切换。滚轮使用地图原生 cursor-anchored zoom；拖动使用地图原生 pan。人物范围只在用户点击“适应全部节点”时调用 `fitBounds`。

覆盖物：人物位置保存为 WGS84 `[longitude, latitude]`。人物、关系线和选中态尽量作为 MapLibre GeoJSON source/layer 渲染；必须使用 DOM 头像 Marker 时，也只通过同一地图实例定位并在 `render` 帧同步，禁止另建 D3 投影或保存屏幕坐标。关系线由端点经纬度生成，跨国际日期变更线时必须处理世界环绕。

信息密度：地名样式使用数据自带的 `min_zoom`、`sort_rank`、`population_rank` 和行政级别。另加屏幕网格预算、碰撞避让、同名要素去重和父子级互斥；同一湖泊的多段几何只能产生一个稳定 label identity，禁止每个线段分别标注。人物节点的显示优先级高于底图标签。

加载与缓存：瓦片在 worker 中解析，视口外请求可取消；平移时保留父级瓦片直到子瓦片就绪，避免切口。浏览器端设置有上限的内存/Cache Storage 缓存；断网时使用小型全球轮廓与已缓存瓦片。用户事实数据不进入远程瓦片服务。

迁移边界：保留现有 `geocoding.ts` 的地点确认结果和项目数据模型；删除 `GeographyCanvas` 中的 D3 投影、全量 path 重算、焦点国家推导和静态半径过滤。旧的本地 Natural Earth 文件仅可作为断网全球轮廓或测试 fixture，不再作为高倍率交互底图。

### ADR-008：弹窗模式与功能分频

状态：**已决定，网页端当前阶段执行（2026-08-24）。**

选择：现有 Web SPA 增加 `?host=popup` 弹窗模式——`App.tsx` 按 URL 参数渲染紧凑界面（文件夹/图谱列表 → 画布），弹窗内只提供查询与轻编辑（添加人物/关系、句子解析、地理图预览、基本信息编辑）；详细编辑（布局与固定、归类维度、路径计算、导入导出、撤销重做体系）通过"在完整工作台编辑"跳转全屏工作台。弹窗、划词气泡、移动端底部抽屉共用同一紧凑界面组件，仅宿主容器不同。

理由：阅读场景可用空间有限，侧边栏嵌入完整工作台会挤占正文并形成"网页端翻版"；功能分频让弹窗保持轻量，同时保留全屏深度编辑能力。句子解析是阅读场景核心功能，采用"选中文本 → 气泡 → 候选确认 → 写入"的划词交互；解析候选确认复用现有 `SentenceParsePanel` 与 `commitCurrentProject` 提交语义，派生结果必须经确认才写入事实库。

代价：弹窗与全屏两套布局需要共享同一数据源与选择状态（当前项目、选中对象），通过既有 IndexedDB 与领域命令保证一致性；紧凑界面需要复用而非复制现有组件，避免出现第二套业务逻辑。移动端触控交互（长按连线、双指缩放、底部抽屉）属于后续阶段，另行适配。

### ADR-009：冻结旅程图前端入口，保留兼容数据（2026-09-16）

选择：停止暴露 `GraphType = "journey"` 的创建、打开和编辑入口；保留 `journey` 字段、领域辅助函数、校验和导入导出兼容性，不做删除或迁移。

理由：现有旅程图把站点、成员和事件归属作为另一套手工维护的数据，与章节进度、人物关系和地理位置的事实表达重叠，尚未证明对泛小说阅读有独立价值。母图—子图重构会扩大为叙事线产品，不能以视觉改造掩盖尚未验证的需求。

恢复条件：只有在移动路径主导的真实场景中验证出高频任务，并可由章节和事件地点自动生成大部分阶段数据时，才以“叙事线”重新设计。该设计必须绑定明确人物或群体，并从文件夹共享事实派生局部视图，禁止复制人物、关系或事件事实。

## 17. 地理图已知故障与对应技术措施

| 故障 | 根因 | 下一实现的强制措施 |
|---|---|---|
| 全球缩放固定进入中国 | 跨级时中心改为人物地理中心 | 缩放锚点取鼠标经纬度；人物不得介入相机 |
| 俄罗斯缩放跳到北京、拖动自动换级 | 最近人物改变焦点国家和 fitted scale | 相机连续；语义级别只由 zoom 派生 |
| 西班牙/俄罗斯空白 | 国家 ID/A3 白名单与回退逻辑不完整 | 全球统一瓦片源，不维护国家白名单 |
| 标签形成轨迹或重复堆叠 | 同名多段要素逐条生成标签，缺少稳定 ID 与碰撞 | 瓦片符号布局、同名去重、rank 与碰撞预算 |
| 图层错位、福建节点在海上 | 底图与覆盖物使用不同投影或不同帧状态 | 单一 MapLibre 投影；节点/边进入同一渲染管线 |
| 拖动中出现切割/未加载区域 | 固定经纬度半径过滤，全量 SVG 没有瓦片生命周期 | 视口瓦片、父瓦片保留、请求取消与加载状态 |
| 高倍率卡顿 | 主线程每帧重投影全量 GeoJSON 和全部标签 | WebGL + worker + 瓦片裁剪；仅处理可视瓦片 |
| 信息密度忽高忽低 | 无层级样式、重要性排序与屏幕预算 | zoom 分层、rank、网格配额、人物优先避让 |

## 18. 当前质量基线与运行方式

- Node.js 要求：`>=24.14.0`；包管理器：npm。
- 验证命令：`npm run lint`、`npm run typecheck`、`npm test`、`npm run build`。
- 2026-08-13 发布基线：18 个测试文件、97 项测试、3 条 Chromium E2E 全部通过；生产构建通过。300 人/1,000 关系浏览器基准满足打开 3 秒、搜索 300 毫秒门槛。当前 Windows 环境全量并行 Vitest 偶发挂起，可靠命令为 `npx vitest run --maxWorkers=1 --no-file-parallelism`。
- Vite 构建提示主 JS chunk 约 676 kB，属于警告而非失败；插件化前需按路由/工作区动态加载，避免把完整 Cytoscape 编辑器塞进每次快速唤起。
- `npm run dev` 默认端口不固定；历史预览曾使用 `http://127.0.0.1:4176/`，接手时必须以终端实际输出为准。
