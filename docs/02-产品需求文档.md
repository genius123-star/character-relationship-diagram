# 人物关系图谱 PRD

版本：v1.1（交接基线，2026-08-12）  
状态：持续实现  
当前形态：桌面浏览器本地 Web 应用  
最终形态：可在阅读、研究和游戏过程中随时唤起的轻量化伴随插件

## 1. 产品判断

当前首版只解决一个问题：帮助个人读者在阅读人物众多的小说时，持续记录人物、理解人物画像，并在复杂关系网络中快速找到人物之间的联系。当前 Web 应用是验证数据模型、图谱交互和计算能力的底座；最终产品不是需要单独打开的重型知识库，而是能覆盖在用户当前任务旁、快速唤起和收起的轻量伴随插件。

产品以人物关系图谱为底座。小说阅读是首个验证场景；科研人物/学派梳理、真实社交关系、亲属称谓和游戏角色网络是后续复用方向。AI 全文抽取、地图识别和跨应用插件化必须建立在核心闭环稳定之后，不能反向拖慢当前版本。

## 2. 目标用户与问题

目标用户是阅读长篇、外国文学、家族叙事或多人群像小说的个人读者。

用户目前需要依靠纸笔、零散笔记或反复翻阅原文记忆人物。随着人物数量和关系增多，主要困难不是缺少人物名单，而是无法快速回答：这个人是谁、还叫什么、何时出现、做过什么、与另外几个人是什么关系。

## 3. 产品目标与成功标准

### 3.1 产品目标

让用户不离开同一张关系图，就能完成人物与关系的录入、查找、理解、编辑和备份。

### 3.2 首版验收闭环

创建《百年孤独》项目 → 添加至少 20 个人物及画像 → 建立至少 30 条双向可读关系 → 拖动并固定节点且不发生重叠 → 按章节观察进度淡化未来内容 → 按家族标签着色 → 搜索并选择多个人物 → 高亮其最短关系路径 → 编辑人物和关系 → 撤销误操作 → 导出 JSON 后重新导入，数据与布局保持一致。

整条任务链全部通过，首版核心能力才视为成立。

### 3.3 容量与性能标准

- 单项目至少承载 300 个人物、1,000 条关系、每人 50 条事件。
- 上述规模下，搜索结果在输入后 300 毫秒内出现。
- 打开项目至图谱可操作不超过 3 秒。
- 节点拖动、画布缩放和平移保持连续可操作，不出现明显停顿。

## 4. 核心概念

- 项目 = 一部小说及其全部人物图谱数据。
- 人物 = 图谱中的节点，名称必填，其他画像字段选填。
- 关系 = 两个人物之间的直接连线，是用户维护的事实源。
- 关系路径 = 系统基于直接关系实时计算的派生结果，不保存为新的关系。
- 观察进度 = 用户在项目时间轴上选择的观察位置，用于淡化当前阶段尚未出现或尚未生效的内容。
- 归类维度 = 用户用于给人物着色的一类标签，例如家族、阵营或身份。

## 5. 核心用户流程

1. 用户在项目首页新建或打开一部小说项目。
2. 用户进入默认的“左侧控制栏 + 扩展图谱”界面。
3. 用户快速添加人物，仅名称必填；需要时继续补充人物画像和事件。
4. 用户选择两个人物建立关系，填写正向关系名称，并按需填写反向称谓和生效章节。
5. 用户通过拖动、固定和重新布局整理图谱；节点始终保持安全距离。
6. 用户通过观察进度、颜色归类和搜索缩小理解范围。
7. 用户选择多个搜索结果，查看这些人物之间的最短关系路径。
8. 用户点击人物或连线，在右侧面板查看和编辑详情；点击空白处关闭面板并恢复扩展图谱。
9. 用户依靠自动保存持续工作，并通过 JSON 文件备份、恢复或迁移项目。

## 6. 功能需求

### FR-01 项目管理

- 用户可以创建、重命名、打开和删除项目。
- 一部小说对应一个项目。
- 创建项目时仅项目名称必填，时间轴默认使用“章”。
- 删除项目必须二次确认，不得影响其他项目。

### FR-02 人物节点

- 用户可以创建、查看、编辑和删除人物。
- 创建人物时仅名称必填；人物名称无需唯一，系统使用内部 ID 区分重名人物。
- 选填字段包括别名、头像、简介、性格标签、身份标签、首次出现章节和备注。
- 用户点击人物节点后，右侧显示人物详情并允许原位编辑。
- 删除人物时只删除该人物的事件，以及以该人物为起点或终点的直接关系。
- 删除前必须显示将被删除的事件数和直接关系数；不得删除其他人物或其他数据。

### FR-03 人物事件与轨迹

- 人物事迹和人生轨迹统一为结构化事件。
- 事件标题必填；章节、描述和地点选填。
- 同一人物的事件按章节排列，未填写章节的事件置于已排序事件之后。
- 用户可以创建、编辑和删除事件。

### FR-04 人物关系

- 用户可以连接任意两个不同人物，并创建、查看、编辑和删除直接关系。
- 必填字段为起点人物、终点人物和正向关系名称。
- 选填字段为反向关系名称、关系描述、开始章节和结束章节。
- 对称关系只填写一个名称，双向读取时使用相同名称。
- 非对称关系可分别保存正向和反向称谓。
- 用户点击连线后，右侧切换为关系详情并允许原位编辑。
- 首版允许同一人物对之间存在多条含义不同的直接关系。

### FR-05 路径计算

- 路径与关系计算使用独立的起点、终点选择器，不占用搜索定位的选择状态。
- 起点和终点支持按姓名或别名筛选已有节点，也支持进入画布点选模式；点选空白处退出该模式。
- 系统计算所选人物之间的最短关系路径，并突出路径中的人物和连线。
- 路径按查询方向正确显示每一段的正向或反向称谓。
- 其他节点和关系淡化但不隐藏，以保留网络上下文。
- 无可达路径时明确显示“未找到关系路径”，不得生成推测关系。
- 路径只用于显示，不自动写回为直接关系。

### FR-05A 关系计算

- 用户选择两个人物后，可以要求系统根据二者之间的直接关系路径计算间接关系。
- 系统沿选定路径按查询方向读取每一段称谓，并组合为最终称谓；例如“我 → 爸爸 → 爷爷的二儿子”可计算为“二叔”。
- 计算结果必须同时显示完整推导链，使用户能够检查起点、终点、每一段方向和最终结论。
- 首版关系计算以规则明确的中文亲属称谓为主；规则库必须可扩展，但不得把普通朋友、观点相似或同属组织等弱语义关系强行合成为确定关系。
- 缺少性别、长幼、血缘或姻亲等必要信息时，系统显示“暂无法确定称谓”，并指出缺少的条件。
- 多条候选路径得出不同称谓时，系统并列展示候选结果和推导链，不得静默选择其中一条。
- 关系计算结果属于派生信息，只用于显示；只有用户明确确认并新建关系后，才能写回为直接关系。

### FR-06 搜索与定位

- 搜索同时匹配名称、别名、简介、性格标签和身份标签。
- 搜索结果必须足以区分重名人物，至少展示头像、名称和一项辅助信息。
- 搜索只负责单人物定位；用户点击另一个结果时替换当前定位，不累积为关系计算选择。
- 多节点路径与称谓计算由独立的“多节点关系计算”功能完成。
- 点击图谱空白区域清除选择并恢复完整图谱状态。

### FR-07 观察进度

- 小说项目默认使用按章节递增的时间轴。
- 用户可以开启或关闭观察进度，并选择当前章节。
- 人物首次出现章节晚于当前章节时，人物及其相关显示淡化。
- 关系开始章节晚于当前章节时，关系淡化。
- 未填写对应章节的人物和关系始终正常显示。
- 首版只淡化未来内容，不隐藏内容，不将该功能命名为防剧透。

### FR-08 标签归类与颜色

- 用户可以创建归类维度及其标签值，例如“家族：布恩迪亚家族”。
- 用户可以为人物设置多个标签。
- 用户每次选择一个归类维度，系统按该维度的标签值自动分配节点颜色。
- 图例必须显示颜色与标签值的对应关系。
- 人物在当前维度没有标签时使用统一的“未分类”样式。

### FR-09 图谱布局

- 图谱支持自动布局、缩放、平移和一键适应全图。
- 节点之间必须存在碰撞约束，不得覆盖或重合。
- 用户拖动节点时，周围未固定节点实时避让并保持最小安全距离。
- 用户拖动后的节点位置自动保存，并可单独固定节点。
- 已固定节点不被自动布局或其他节点拖动改变位置。
- 拖动节点接近固定节点时，拖动节点停在最小安全距离外。
- “重新布局”只重排未固定节点；“重置布局”解除全部固定后重新计算。

### FR-10 自适应详情面板

- 默认状态为固定左栏和扩展图谱，右侧详情面板隐藏。
- 点击人物节点后显示人物详情，图谱收缩为三栏布局。
- 点击关系连线后显示关系详情，图谱收缩为三栏布局。
- 人物与关系之间切换选择时，右侧面板同步切换内容。
- 点击图谱空白处取消选择、隐藏右侧面板并重新扩展图谱。
- 面板切换时保持图谱缩放比例和视野中心，并确保选中对象可见。

### FR-11 自动保存、撤销与重做

- 数据变更完成后立即保存到浏览器本地。
- 支持最近 50 次撤销和重做。
- 操作范围覆盖人物、关系、事件、标签的新增、编辑和删除，以及节点位置变化。
- 一次连续拖动只记为一次操作。
- 页面异常关闭后，重新打开不得丢失已完成保存的操作。

### FR-12 导入与导出

- 用户可以将完整项目导出为一个 JSON 文件。
- JSON 包含人物、头像、事件、关系、标签、时间轴配置和布局位置。
- 用户可以导入合法的项目 JSON，并恢复完整项目。
- 导入前必须校验文件结构；失败时显示原因且不得覆盖现有数据。
- “导出项目”提供格式选择：JSON 用于完整备份与恢复；PNG、JPG 和 PDF 用于分享、打印当前项目的完整关系图。图像类导出必须包含全部节点和关系，不受当前画布缩放、平移和屏幕裁切影响。
- 首版不支持 Excel 或 CSV 导入导出。

### FR-13 轻量化伴随插件（当前实施：弹窗形态）

产品最终形态是可在阅读、研究和游戏过程中随时唤起、不挤占当前任务空间的轻量伴随工具。当前网页端先完成弹窗形态，移动端原生 App 为后续阶段。

- 插件采用弹窗形态而非侧边栏分屏：快捷键唤起后弹出浮层，不压缩阅读正文宽度；再次按快捷键或 Esc 收起，原页面焦点、滚动位置和选区不丢失。
- 唤起后先显示初始界面：文件夹列表、文件夹内的关系图，以及新建文件夹、新建图谱入口。
- 选择目标项目后进入画布。弹窗内画布支持以下能力：
  1. 添加人物与关系。
  2. 句子解析（阅读场景的核心功能）。
  3. 地理图中添加人物与关系、句子解析、缩放平移与"适应全部节点"预览。
  4. 修改人物与关系的基本信息（名称、别名、标签、类型、说明等）。
- 功能分频原则：弹窗内只做"查询与轻编辑"；布局与固定、归类维度管理、关系路径计算、导入导出、撤销重做体系等详细编辑跳转全屏工作台完成，全屏工作台不挤占阅读页。
- 句子解析交互借鉴划词翻译的唤起方式：选中文本 → 浮出解析气泡 → 候选确认面板（人物/关系/特征/地点/事件分组）→ 用户确认后写入并收起。解析结果是派生候选，必须经用户确认才写入事实库；写入采用"落库后再返回"的提交语义。
- 阅读场景可关联当前书籍或页面：解析结果可携带当前阅读章节，与观察进度联动。研究、游戏场景的关联方式与权限边界在对应阶段单独验证。
- 核心数据保持本地优先。插件不得未经确认读取页面正文、剪贴板、游戏进程或上传用户资料。
- 移动端形态为原生 App，重点场景是平板阅读：底部抽屉或悬浮球承载速览与解析，内置阅读器优先，触控画布只做查看与轻编辑。移动端 App 与网页端共享同一领域核心，属于后续阶段，不在当前网页端范围。
- 插件化验收标准：用户从当前内容唤起工具、找到人物并查看直接关系不超过 3 次操作；解析一句含人物与关系的文本并确认写入不超过 3 次操作；收起后原页面焦点和阅读位置不丢失。

## 7. 界面结构

- 项目首页：创建项目、打开项目、导入项目和删除项目。
- 顶部工具栏：添加人物、添加关系、撤销、重做、重新布局、适应全图、导入和导出。
- 左侧控制栏：项目信息、搜索、观察进度、颜色归类和图例。
- 中间图谱：人物节点、关系连线、路径高亮、拖动和画布控制。
- 右侧详情面板：按当前选择展示人物详情或关系详情，默认隐藏。

## 8. 关键异常与边界

- 重名人物必须可并存，任何更新和删除均按内部 ID 执行。
- 人物不存在时不得创建关系；关系的起点与终点不得相同。
- 删除人物后，任何关系不得继续引用已删除人物。
- 头像文件损坏或格式不支持时，保留原人物资料并显示默认头像。
- 搜索无结果、人物之间无路径、项目为空时均提供明确空状态。
- 导入数据中的 ID 冲突、缺失引用或非法字段必须在写入前处理或拒绝，不得产生半导入状态。
- 多条等长最短路径存在时，首版可展示其中一条确定路径；结果必须稳定，刷新后不应随机变化。

## 9. 首版范围之外

- 账号、登录、云同步、跨设备同步和多人协作。
- 自动解析小说全文或通过 AI 抽取人物与关系。
- 隐藏未来内容的真正防剧透模式。
- 科研工作区、真实社交工作区和亲属称谓计算。
- AI 语义聚类、观点聚类、性格聚类和关系社群发现。
- 浏览器插件、写作软件插件和论文工具集成。
- Excel、CSV 和其他通用表格格式交换。
- 地理叙事图谱、真实地图底图、地点/势力范围识别和旅行轨迹可视化；该能力列入后续版本规划，不进入 v1.0 验收闭环。

## 9.1 当前阶段：真实地理关系图

### 问题与目标

现有人物关系图只能回答“谁与谁有关”，无法直观回答“人物位于哪里、势力覆盖哪里、故事如何沿地理空间推进”。地理叙事图谱将人物、地点、势力、事件和行程放入同一空间视图，服务于地域政治叙事、旅行文学、历史事件和人物迁徙研究。

### 核心模式

1. **连续地理视图**：不提供“全球/局部”切换按钮，而以全球、洲际、国家、地区或省州四档语义比例尺承载同一张地图。空图默认全球；全部已匹配节点位于同一国家时自动进入国家视图；跨国但同洲时进入洲际视图；跨洲时回到全球视图。用户可继续放大进入国家及地区或省州视图，即使当前节点横跨多个国家。
2. **旅行叙事模式（历史原型，2026-09-16 起冻结）**：曾以地点序列 A → B → C → D 表示主人公行程，并为每个地点维护局部人物—事件图。该模式与章节进度、事件地点和人物关系重复维护，当前不作为可见产品能力；保留历史数据和实现，恢复条件见 §13.5。
3. **自由地理画布模式**：当用户没有真实地图或故事地点为虚构世界时，允许使用自定义底图或空白空间手工放置地点、人物和势力范围。

### 计划需求

- 文件夹是共享数据容器，统一保存人物、关系、资料和事件；每张图仅保存成员引用、布局、进度与专属配置。
- 地理图允许从当前文件夹搜索并多选人物和关系加入；在地理图新建的事实同时写入文件夹共享库。
- “从当前图移除”只删除视图引用；“从文件夹永久删除”才删除共享事实并清理所有图中的引用。
- 地点成为独立实体，至少包含名称、别名、类型、真实经纬度、行政区域、说明和匹配状态。
- 人物、事件和关系可关联一个或多个地点，并允许记录到达、离开、停留和发生章节。
- 势力范围使用点、线或多边形表示；同一地区允许存在重叠、争夺和随时间变化的势力范围。
- 地图自动根据已匹配节点范围选择语义比例尺；每档内部可有限缩放，越过阈值后进入相邻档位。用户主动拖动或缩放后锁定当前视角，“适应全部节点”恢复自动取景。
- 全球档使用可 360° 旋转的 3D 地球；洲际、国家或地区档使用近俯视二维地图。视图变化不得改变人物与关系事实数据。
- 地理图人物使用与普通关系图一致的独立圆形节点；画布上不常驻人物名称、地点或资料卡，点击节点后才在右侧资料区显示完整信息。
- 关系类型、关系名称与分类预览默认收起为画布右侧悬浮按钮；用户点击后展开编辑面板，完成设置后可再次收起，面板不得遮挡顶部比例尺控件。
- 图层仅包含行政区划、海岸线、主要湖泊、河流、山地图例和可选经纬网；所有辅助图层可独立开关和叠加。
- 不提供卫星影像、等高线、真实高程起伏、道路或复杂交通网络。
- 旅行叙事按章节或时间排序地点，地点小图可展开、折叠；跨地点关系必须保留来源和方向。
- 系统联网解析人物“地区/势力”字段并缓存经纬度；唯一结果可自动放置，同名地点必须展示候选并由用户确认。
- 系统不得仅凭人物“地点/所属势力”文本直接覆盖数据；同名地点、历史地名、行政区变化和虚构地点必须提示歧义。

### 验收示例

用户为《在路上》建立美国地图项目 → 创建主人公行程 A → B → C → D → 为每站添加遇见人物和事件 → 展开各站局部关系图 → 建立跨地点人物联系 → 调整观察章节 → 地图只突出当前进度及以前的地点、人物和关系 → 切回普通关系图后人物与关系数据保持一致。

比例尺验收：空图显示全球 → 新增北京节点后自动进入中国范围 → 新增东京节点后自动扩展至亚洲 → 新增柏林节点后自动扩展至全球；手动平移后新增节点不抢夺视角，点击“适应全部节点”后重新按上述规则取景。

### 明确不包含

- 首个地理版本不自动从整本小说生成完整地图。
- 首个地理版本不支持用户上传底图、虚构世界地图或历史疆域复原。
- 不把地图匹配结果当作历史或现实事实；AI 推断必须显示来源、置信度和待确认状态。
- 暂不提供实时导航、GPS 追踪或商业 GIS 分析能力。

### 关键风险与待确认项

- 地图版权与授权范围：优先支持用户自有图片及开放授权底图。
- 真实经纬度、历史地图坐标和虚构地图相对坐标需要三套明确的数据语义。
- “人物所在地”“事件发生地”“势力覆盖区”不可合并为一个字段，否则无法表达旅行、迁徙和势力变化。
- 地点小图与全局人物图同时展开时可能产生严重视觉拥挤，需要先用 20 个地点、100 个人物的原型验证可读性。

## 10. 风险与产品取舍

- 手工录入成本可能降低持续使用意愿；首版先验证图谱是否足够有价值，AI 抽取不提前进入范围。
- 自动布局在 300 个节点时可能造成视觉拥挤；搜索、淡化、固定节点和归类必须共同承担可读性，而不是只依赖布局算法。
- 浏览器本地存储存在用户清理数据的风险；JSON 导出必须在界面中作为明确的备份能力呈现。
- 头像嵌入 JSON 会增加文件大小；首版优先保证单文件可迁移，达到实际容量瓶颈后再考虑压缩或资源分离。

## 11. 发布验证

首版以本地可运行版本进行任务测试。测试者使用同一份《百年孤独》样例任务完成第 3.2 节的整条链路；记录完成率、阻断点、误操作次数和完成时间。任何数据丢失、关系引用错误、节点重叠无法解除或导入后数据不一致，均视为发布阻断问题。

## 12. 下一阶段

Web v1.0、撤销重做、文件夹和本地回收站已经完成。当前暂停插件开发，优先交付文件夹共享数据底座与真实地理关系图；首个纵向切片为旧项目无损迁移、跨图选择人物和关系、两级删除语义，以及极简全球/局部地图原型。

## 13. 下一阶段修订：地理图内核重建

### 13.1 阶段判断

现有 SVG + 全量 GeoJSON 原型已经验证人物定位、地理关系线和语义比例尺的产品价值，但不具备继续迭代的技术基础。下一阶段不再修补现有地图，而以适合轻量插件的连续矢量地图内核替换它。人物、关系和项目资料继续全部本地保存；底图允许联网按当前视口读取并进行有限本地缓存。

### 13.2 必须解决的问题

1. 全球视图进入二维地图时忽略鼠标位置，总是回到已匹配人物的地理中心，节点集中在中国时表现为固定跳到中国。
2. 拖动或跨越比例尺阈值时，系统会重新选择最近人物和“焦点国家”，继而改变投影中心、缩放系数和图层过滤范围，造成画面跳转、比例尺自动切换和俄罗斯缩放后跳回北京。
3. 全球、洲际、国家、地区或省州并非同一连续相机上的语义标签，而是会更换参数的地图模板；相邻档位的内容、中心和视觉尺度不能连续衔接。
4. 国家适配和行政区过滤仅覆盖少数硬编码国家，西班牙、俄罗斯等地区会使用错误的回退范围，出现大面积空白或加载全球无关要素。
5. 全量 50m GeoJSON 在主线程随每次拖动重新投影，放大后可见内容减少但计算量不减，造成高倍率拖动卡顿。
6. 静态经纬度半径过滤不能覆盖真实视口；拖动到过滤范围外时不会及时补充内容，形成未加载、切割或空白区域。
7. 行政区、水系和地名缺少按重要性、缩放级别和屏幕空间的密度控制：同名湖泊因多段几何被重复标注并形成“文字轨迹”，部分地区标签堆叠，另一些地区完全空白。
8. 底图、标签、人物节点和关系线由不同渲染/状态链计算，拖动时可能读取不同帧的相机参数，导致图层错位以及福建节点漂到海面等相对位置偏移。
9. 缩放锚点没有保持鼠标所在经纬度不动；用户主动探索地图时，节点适配逻辑错误地抢夺相机控制权。
10. 数据加载失败或尚未完成时缺少明确的加载、回退与重试状态，用户只能看到空白，无法区分该地区无信息还是图层没有加载。

### 13.3 目标体验与约束

- 地图相机只有一份权威状态：`center + zoom + bearing + pitch/projection`。拖动只改变中心，滚轮只围绕鼠标锚点改变缩放；两者都不得根据人物或国家自动改写相机。
- 全球、洲际、国家、地区或省州只是连续 zoom 区间的用户可读名称，不触发更换数据源、重新选国或跳转。只有“适应全部节点”可以主动根据人物改变相机。
- 底图、地名、人物节点和关系线必须使用同一个地图实例、同一投影和同一帧相机状态。人物事实保存经纬度，不保存易失的屏幕坐标。
- 使用屏幕信息预算控制密度，而不是尽可能显示全部地名。全球显示国家和大洲；洲际增加首都与主要河湖；国家增加一级行政区、省会和必要地形；地区增加二级行政区、城市及局部水系。标签必须去重、避让并按重要性排序。
- 不显示道路、建筑、商店、卫星影像、等高线和持续更新的影像。空旷地区用少量行政名称、主要水系和山地图例提供空间参照，不用无意义文字填满。
- 插件不内置完整全球数据。联网时按可视瓦片读取；保留小型全球轮廓作为断网降级，并缓存近期视口。用户的人物、关系、地点确认和视图配置始终本地保存。

### 13.4 验收标准

- 在全球任意经纬度使用滚轮进入二维地图，鼠标下的地理位置偏移不超过 8 px，不跳向任何人物节点。
- 连续拖动 10 秒以及跨越全部语义比例尺时，地图中心、比例尺和投影保持连续；松开鼠标无额外位移。
- 北京、福建、纽约、西班牙、俄罗斯和南半球各选一个地点重复缩放与拖动，节点相对海岸线和行政边界不漂移，允许误差不超过 2 px。
- 当前视口内不存在重复同名标签轨迹；标签不相互覆盖人物节点，默认可见标签数量遵循样式预算。
- 拖入尚未缓存的区域时显示已有父级瓦片或明确加载状态，不出现透明切口；加载失败可重试并有断网降级。
- 典型 1920×1080 视口中拖动保持主观连续，目标 60 FPS，最低不得持续低于 30 FPS；人物和关系数量按既有 300 人/1,000 关系基准验证。
- 地图内核及底图数据的许可证、署名、缓存范围和导出规则有书面记录。

### 13.5 旅程图冻结决策（2026-09-16）

旅程图不再作为与人物关系图、地理位置图并列的可见前端视图，也不继续投入“母图—子图”重构。当前人物关系图、章节观察进度和地理图已分别覆盖“谁与谁有关”“截至何章已发生什么”“人物在哪里”；现有旅程图需要用户重复维护站点、人物和事件归属，却没有证明能为首版的泛小说阅读场景提供独立且高频的价值。

`journey` 项目数据、导入导出兼容性和既有实现保留，不删除也不改写已有项目；前端不提供创建、打开或编辑旅程图的入口。只有产品明确聚焦公路小说、迁徙叙事、行军或冒险等“移动路径即主线”的场景，并能从章节和事件地点自动推导大部分行程信息时，才重新评估。届时应把它定义为“叙事线”：由明确人物或群体拥有，母图展示阶段顺序，子图从共享事实中派生局部人物、事件和关系，而不是复制维护第二份数据。
